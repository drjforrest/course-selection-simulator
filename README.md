# MSHI Course Selection Simulator

Students build a term-by-term plan for the MS in Health Informatics (no concentration) and print it. Faculty set which courses run in which term.

- Student view: `/`
- Faculty view: `/faculty` (password protected)

Covers three program versions: Boston (on-ground), Online (general), and Online (Vancouver).

## Rules the student planner enforces

Hard rules. The planner refuses a move that breaks one and says why:

- Total credits can't go above 36.
- A prerequisite has to be completed or placed in an earlier term (catalogue prerequisites).
- HINF 7701 needs at least 3 prior semesters of graduate study (catalogue).
- A course can only go in a term where it runs, in a format the student's program version can take. Boston students can take on-ground, hybrid and online sections. Online and Vancouver students can take online sections only.

Shown as advice. The plan still works:

- More than 3 courses in one semester.
- An empty Fall or Spring term between used terms. Fall and Spring must be consecutive, and a semester off needs an exception from the program director. Summer terms are optional, so an empty summer produces no warning.
- No schedule data for a course in that term.
- HINF 5101 not in the first term, or HINF 7701 not in the last term.
- Both HINF 6215 and EMGT 5220 taken. Only one counts.

Degree requirements: HINF 5101, HINF 5105 (or HINF 5106 for Vancouver) and HINF 7701, plus two courses from each pool (Business Management, Technical, Health Informatics, General Electives), with 33 to 36 credits in total. Courses are assigned to requirements automatically so that as many requirements as possible are filled. At most one DA/INSH course can count toward Technical. HLTH 5800 counts toward Technical in the general online version and toward Health Informatics everywhere else.

Intake: every plan starts in Spring or Fall; there is no summer intake. When a plan is built, HINF 5101 and HINF 5105/5106 (unless already completed) go in the first term each runs. With a Spring start both land in term 1. With a Fall start, 5101 lands in Fall and 5105/5106 in Spring. Students can move them, and faculty term settings change where they land.

Student data stays in the browser's memory only. Nothing is stored on the server or in the browser. Log out or closing the tab clears the plan, so students should print before they leave.

## Term offerings

For any term, each course's offering comes from the first source that has data:

1. A faculty **one-term exception** for that exact term. It does not carry to other years.
2. The course's **faculty schedule**, set with "Change schedule": the seasons and formats it runs in, from a starting term onward. Use this for catalogue changes.
3. The **program model** for the intake courses: HINF 5101 runs every Spring and Fall, and HINF 5105/5106 every Spring, in all formats and in no other season.
4. The **course schedule spreadsheet** for the same season, using the most recent year it covers.

So if faculty change nothing, Spring 2027 looks like Spring 2026.

The spreadsheet covers every HINF course for Spring 2025 through Fall 2026. For PHTH, DA and INSH it only covers the Spring 2025 sections it lists. EMGT 5220, HLTH 5800, PHIL 5110, PHTH 5226, PHTH 5232, PHTH 7400 and PHTH 7440 have no schedule data, so students see them as "unconfirmed" until faculty set them.

The spreadsheet has a few numbering errors, which `scripts/build_base.py` corrects: 6401 becomes 6400, 5103 becomes 5102, and 7702 becomes 7701.

## Data

- `data/base.json` is generated by `npm run build-data` from `scripts/schedule.xlsx` and `scripts/catalog_courses.json` (2026–2027 catalogue). Pools and prerequisites are in `scripts/build_base.py`. Rebuilding needs Python and openpyxl.
- `scripts/schedule.xlsx` is gitignored and not in the repository, because it contains instructor names and enrolment figures. Copy it from OneDrive (*Health Informatics Course Schedule.xlsx*) into `scripts/` before rebuilding the data.
- `data/overrides.json` holds faculty changes (course schedules, one-term exceptions, credits and prerequisites). The server writes it. Back it up.

## Run locally

```bash
FACULTY_PASSWORD=choose-one npm start
```

Then open http://127.0.0.1:3000. Requires Node 18 or later. There are no npm dependencies.

```bash
npm test
```
